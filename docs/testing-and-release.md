# Тестирование и подготовка релизов

## Тестовый контур

Рабочий проект содержит модульные тесты и интеграционные тесты с PostgreSQL.

Отдельно выделены архитектурные контрактные тесты. Они проверяют свойства
платформы, которые нельзя случайно сломать рефакторингом:

- общий предельный срок принадлежит всей волне получения данных;
- DAG содержит барьер конечных состояний;
- обработка тенанта начинается после барьера;
- `ClientConfig.clinics[]` остается единственным актуальным списком клиник тенанта;
- режим получения данных проверяется до обращения к источнику;
- внешний `source_key` не становится внутренним хэш-ключом;
- уже примененные миграции не меняются незаметно;
- рабочий контур не содержит веток поведения только для тестов;
- публикация семантического слоя остается изолированной по тенантам.

## Интеграционные тесты PostgreSQL

Интеграционные тесты проверяют служебные блокировки PostgreSQL, `for update skip locked`,
откат транзакций, вставку и обновление, ограничения и переходы состояний семантических снимков
и переходы состояний получения данных.

## Безопасность миграций

Для каждой примененной миграции хранится контрольная сумма.

Если файл изменился после применения, механизм миграций не выполняет его повторно
молча.

## Образы релиза

Рабочая система собирает образы приложения заранее.

Целевой сервер не должен собирать приложение из исходников.

Для автономной локальной поставки используются заранее подготовленные архивы
образов.

## Проверка перед первым запуском

Перед первой загрузкой тенанта выполняется предварительная проверка.

Проверяются конфигурация, наличие секретов, доступность DWH и источников,
свободное место на диске, состояние миграций, синхронизация времени, состояние
служебных компонентов и контракты источников.

Рабочий установщик и реальные адреса сервисов в публичную версию не включены.
